# Power BI

The semantic model lives in Git as text (PBIP + TMDL), so changes are reviewable and tested.

```
powerbi/
  GridPulse.pbip                      open this in Power BI Desktop
  GridPulse.SemanticModel/definition/ TMDL: 8 tables, 23 DAX measures, 4 relationships, 2 parameters
  GridPulse.Report/                   report: 5 pages, 33 visuals bound to the model (generated by scripts/gen_pbir.py)
scripts/gen_tmdl.py                   regenerates the TMDL (a test fails if the committed files drift)
```

## Open it
1. Start the warehouse and fill it: `docker compose up -d postgres`, `gridpulse load-warehouse`,
   `cd dbt && dbt build`, then `gridpulse walk-forward --first-test-month 2025-10-01 --n-months 13`
   and `gridpulse analyze` (creates `gold.walk_forward_backtest` and the three small
   `gold.analysis_*` tables used by the first page).
2. Open `powerbi/GridPulse.pbip` in Power BI Desktop. On first refresh, give the PostgreSQL
   credentials (local: user `gridpulse`, the password from `docker-compose.yml`). Parameters
   `PgServer` / `PgDatabase` default to `localhost` / `gridpulse`; change them under Transform data.
3. The report definition (5 pages, 33 visuals) is generated by `scripts/gen_pbir.py` and committed.
   Save changes made in Desktop as PBIP so they go to Git.

## Pages
| Page | Content |
|---|---|
| The answer | The central question, four KPI cards (error vs naive, MAE, battery revenue vs naive, naive capture of perfect foresight), battery revenue by forecast, error reduction under weather noise |
| Market overview | Cards, daily price line, month and year slicers, negative prices by hour and a month x hour matrix |
| Prices vs drivers | Wind vs price scatter, price by hour, renewable share by weekday x hour, region slicer |
| Forecast vs actual | MAE cards, interval coverage, actual vs naive vs weather model, MAE by test month, caveat text |
| Pipeline health | Freshness and row-count cards |

Required caveat on the forecast page (already in the report): the weather model uses observed
weather as a stand-in for a forecast, so its error is an optimistic upper bound (see
[model-card.md](model-card.md)).

## Status and limits
- Checked without Power BI: tests verify measure metadata, relationships, DAX column references,
  generator sync, that every visual binds only existing tables, columns and measures, and the
  column list of the warehouse tables against the live Postgres `gold` schema.
- The report JSON is validated against Microsoft's published PBIR schemas
  (`python scripts/validate_pbir.py`, needs network). This caught a real error in the first
  skeleton (an invalid `report.json`), now fixed.
- Opening in Desktop and refreshing needs the PostgreSQL credentials, which stay with the user.
  Whether each visual renders as intended after a refresh has not been verified by the author's
  tooling; formatting (colours, conditional formatting on the matrices) is left at defaults.
- The data connection is Import mode over a local PostgreSQL; publishing to the Power BI service
  needs a gateway for a local database and an account that allows publishing. The portfolio
  alternative is screenshots or a short screen recording plus these files.
- Time-intelligence measures are not included; the model has no marked date table yet.
